## Route {#route}

Route описывает маршрут. Для HTTP его задают метод и путь. Например, в [быстром старте](../quick-start/index.mdx) маршрут `users-by-id` подходит и для `GET /users/123`, и для `GET /users/456`: в его пути `/users/{id}` меняется только `id`.

## Case {#case}

Case задаёт условие внутри маршрута. Например, `user-123` проверяет `id` из пути, поэтому подходит только для `/users/123`. Условия могут проверять и другие данные, например параметры запроса, заголовки или тело. [Как Decoy проверяет условия](../routes/index.md#case-match).

## Behavior {#behavior}

Behavior задаёт действие для запроса, который прошёл проверку Case. У `user-123` может быть два таких правила: `success` возвращает данные Ады, `missing` возвращает 404. Выберите другое правило, чтобы проверить второй исход с тем же запросом.

## Behavior address {#behavior-address}

Адрес правила записывается как `route:case:behavior`. Например, `users-by-id:user-123:missing` выбирает правило `missing` для условия `user-123` в маршруте `users-by-id`.

## Collection {#collection}

Collection перечисляет правила, которые Decoy включает вместе. Тест может одним вызовом перейти с `happy-path` на `user-missing`, даже если коллекции меняют ответы сразу нескольких маршрутов. [Как составить коллекцию](../collections/index.md).

## Scenario

Scenario описывает то, что вы хотите проверить в приложении. Например, что произойдёт при оформлении заказа, если сервис не найдёт пользователя. В Collection вы перечисляете правила, по которым Decoy воспроизведёт этот сценарий.

## Session

У каждого теста может быть своя сессия (Session), чтобы он мог менять ответы, не мешая другим тестам на том же сервере. Передайте одно и то же значение `x-mock-session` в запросе к Control API и в запросе, на который должен прийти новый ответ. [Сессии в параллельных тестах](../sessions-and-control/index.md).

## Selection

Selection — это активная Collection и переопределения Behaviors для одной Session. Например, тест может оставить `happy-path` активной, но переопределить Behavior одного Case, чтобы получить 404.

## Catalog

Catalog содержит Routes, Cases, Behaviors, Collections и настройки, загруженные Decoy. Sessions используют общий Catalog, но независимо выбирают, какие Behaviors активировать.

## Fail-closed

Если мок не подходит к запросу, Decoy отвечает с объяснением. Например, для HTTP-запроса по ненастроенному пути он сообщит, что мок не найден. Для обращения к реальному серверу требуется явно выбрать Behavior [Passthrough](#passthrough).

## Passthrough {#passthrough}

Passthrough пересылает подходящий запрос реальному сервису. Например, можно имитировать `GET /users/123`, а запросы по другим пользователям отправлять на сервер разработки. [Как настроить Passthrough](../routes/index.md#passthrough-behavior).

## Order-based matching

Decoy проверяет активные условия снизу вверх по коллекции. Если запрос подходит под два условия, сработает то, которое стоит ниже, даже если оно более общее. [Почему порядок записей важен](../collections/index.md).

## Request envelope

Request envelope содержит значения одного запроса, доступные Case или шаблону. Для `GET /users/123` в Request envelope HTTP входят путь и извлечённый ID. В gRPC туда входят метод и декодированное сообщение.

## Message envelope

В открытом WebSocket каждое входящее сообщение получает свой Message envelope. Case может использовать декодированное сообщение вместе с данными соединения, например с его путём или параметрами запроса. [Сопоставление сообщений WebSocket](../websocket/index.md).

## Template context

В контексте шаблона (Template context) хранятся данные, которые Decoy может подставить в ответ. Например, ID из пути запроса можно вывести в теле ответа. [Как написать шаблон ответа](../routes/index.md#templates).

## Standard function

Standard function встроена в язык выражений Decoy. Например, `uuid()` может сгенерировать ID запроса прямо в шаблоне ответа.

## Controller

Controller меняет Selection для Session. Вызовите `useCollection`, чтобы переключить весь Scenario, или `useRoute`, чтобы выбрать отдельное Behavior.

## Control API

Control API позволяет вызывать операции работающего сервера по HTTP. Например, POST-запрос к `/__decoy__/control/useCollection` переключает Collection для указанной в запросе Session. [Запросы к Control API](../sessions-and-control/index.md#control-api).

## Router

Router — объект, через который тест управляет своей Session. Например, в Playwright вызов `decoy.useCollection('happy-path')` меняет ответы только для этого теста. [Как использовать фикстуру Playwright](../playwright/index.mdx).

## Connection

Объект Connection даёт доступ ко всем открытым соединениям одного маршрута в одной сессии. Когда браузер откроет WebSocket, тест сможет отправить через этот объект сообщение всем клиентам, подключённым к маршруту в этой сессии. [Как отправить сообщение из теста](../sessions-and-control/index.md#send).

## Pipeline

Pipeline задаёт порядок преобразований полезной нагрузки транспорта. Например, Pipeline WebSocket может декодировать двоичные данные перед проверкой Case. У именованного Pipeline есть отдельные списки входных и выходных шагов. [Как настроить Pipeline](../transformer-pipelines/index.md).

## Transformer

Transformer принимает одно значение и возвращает другое. Можно менять формат, содержимое или и то и другое. Например, первый шаг распаковывает байты, а следующий разбирает их в объект. Ещё один Transformer может взять объект и вернуть только его `id`. Каждый шаг передаёт результат следующему. Transformer может работать как команда или как постоянный воркер. [Как написать воркер с TypeScript SDK](../transformer-sdk/index.mdx) или [реализовать протокол воркера](../transformer-worker-protocol/index.md).

## Pipeline step

Шаг цепочки (Pipeline step) запускает один Transformer или встроенное преобразование gRPC. Результат шага становится входными данными для следующего.

## Transformer worker

Воркер (Transformer worker) выполняет входные или выходные преобразования в отдельном процессе, который продолжает работать между вызовами. Его можно написать с помощью [TypeScript SDK](../transformer-sdk/index.mdx) или реализовать [протокол воркера](../transformer-worker-protocol/index.md) самостоятельно.
