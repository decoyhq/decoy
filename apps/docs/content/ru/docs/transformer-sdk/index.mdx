# @decoyhq/transformer

С этим SDK можно написать воркер Decoy на TypeScript. Воркер переводит данные из формата приложения в JSON для условий и правил, а на выходе может преобразовать JSON обратно. Например, он может разобрать MessagePack, снять двоичный заголовок перед protobuf или распаковать сжатые данные. Воркеры работают в маршрутах HTTP, gRPC и WebSocket. См. [Настройку цепочки преобразований](../transformer-pipelines/index.md).

Установите SDK и библиотеку MessagePack, используемую в этом примере (Node.js 24+):

  command={{
    npm: 'npm install @decoyhq/transformer @msgpack/msgpack',

Этот пример преобразует двоичные и текстовые сообщения WebSocket. Сохраните его в `workers/envelope.ts`:

```ts title="workers/envelope.ts"
import { decode, encode } from '@msgpack/msgpack'
import { defineTransformer, miss } from '@decoyhq/transformer'

export default defineTransformer({
  name: 'envelope',
  version: '1.0.0',

  async input(bytes, ctx) {
    if (!(bytes instanceof Uint8Array)) return bytes
    if (ctx.frame === 'text') return JSON.parse(new TextDecoder().decode(bytes))

    const { type, data } = decode(bytes) as { type: string; data: Uint8Array }
    if (!(await ctx.protobuf.has(type))) miss(`unknown type ${type}`)
    return { type, data: await ctx.protobuf.decode(type, data) }
  },

  async output(value, ctx) {
    if (typeof value !== 'object' || value === null || !('type' in value)) {
      return JSON.stringify(value) // a string goes out as a text frame
    }

    const { type, data } = value as { type: string; data: unknown }
    return encode({ type, data: await ctx.protobuf.encode(type, data) }) // bytes: binary
  },
})
```

Зарегистрируйте воркер в `decoy.yaml` и добавьте его в именованную цепочку:

```yaml title="decoy.yaml (excerpt)"
transformers:
  env:
    worker: [node, ./workers/envelope.ts]

pipelines:
  approvals-ws:
    input: [env]
    output: [env]
```

- `defineTransformer` возвращает Transformer и обслуживает его через `stdin` и `stdout`, если процесс запустил Decoy (`DECOY_TRANSFORMER=1`). Модульный тест может импортировать файл и вызвать `input` напрямую.
- Пакет может экспортировать фабрику, которая принимает типизированные настройки и возвращает `defineTransformer(...)`. Пользователи вызывают фабрику в своём файле воркера.
- Для WebSocket вызов `miss(reason)` в `input` пропускает фрейм: Decoy записывает причину и оставляет сокет открытым. Любое другое исключение — ошибка воркера, в которой указаны Transformer, Behavior и значение, вызвавшее ошибку.
- При обработке входящего кадра WebSocket `ctx.frame` равен `'text'` или `'binary'`. И на входе, и на выходе доступны данные соединения `ctx.connection` в виде `{ id, route, session }` и общий для этого соединения `ctx.state`. В HTTP, gRPC и при проверках запуска каждый вызов получает новый словарь состояния.
- Воркеры HTTP получают `ctx.request` на входе и выходе, включая выход Passthrough. Это доступный только для чтения снимок исходных метода, пути и заголовков (имена в нижнем регистре). В заголовках могут быть cookie и учётные данные; не записывайте их в журнал. При проверках запуска контекста запроса нет.
- `ctx.protobuf.has/decode/encode` используют proto-файлы, уже скомпилированные Decoy.
- Во время обработки вызовов `console.log` пишет в `stderr`, поскольку `stdout` занят протоколом. Decoy выводит каждую строку `stderr` с меткой воркера.

Чтобы реализовать воркер на другом языке, см. [протокол обмена](../transformer-worker-protocol/index.md).
