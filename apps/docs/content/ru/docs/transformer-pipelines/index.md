# Настройка цепочки преобразований

Преобразование (Transformer) достаточно описать один раз в `decoy.yaml`, а затем его можно использовать в нескольких цепочках (Pipelines). В примере `gzip` запускает команду, а `approvals` обращается к воркеру. На входе цепочка `approvals-feed` распаковывает данные и передаёт их воркеру. На выходе порядок обратный: сначала воркер обрабатывает данные, затем `gzip` сжимает результат.

```yaml title="decoy.yaml (excerpt)"
transformers:
  approvals:
    worker: [node, ../workers/approvals.ts]

  gzip:
    input: [gzip, -dc]
    output: [gzip, -c]

pipelines:
  approvals-feed:
    input: [gzip, approvals]
    output: [approvals, gzip]
```

## Подключите цепочку к маршруту

Задайте `pipeline` рядом с `id`, `transport` и `match` в файле маршрута. Decoy выполняет шаги в порядке записи и на входе, и на выходе. Одну цепочку можно подключить к нескольким совместимым маршрутам.

```yaml title="Route excerpt: select a named Pipeline"
pipeline: approvals-feed
```

| Транспорт                                              | Что преобразует Pipeline                                                                                                                         |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| [HTTP](../routes/index.md#http-body-pipelines)         | Тела запросов и ответов.                                                                                                                         |
| [gRPC](../grpc/index.md#pipelines)                     | Байты запросов и ответов в кадрах. Если Transformer работает с декодированными сообщениями, добавьте `grpc-frame` и `protobuf` в нужном порядке. |
| [WebSocket](../websocket/index.md#websocket-pipelines) | Полезную нагрузку входящих фреймов и исходящие сообщения, в том числе отправленные через Control API.                                            |

В именованном Pipeline gRPC настроенный Transformer имеет приоритет над одноимённым встроенным шагом. Рабочие настройки есть в [общем примере для HTTP и WebSocket](https://github.com/decoyhq/decoy/tree/main/examples/ws-transformer-node) и в [примере для gRPC](https://github.com/decoyhq/decoy/tree/main/examples/grpc-node).

## Проверка и ограничения выполнения

При загрузке маршрутов Decoy проверяет, что каждое преобразование существует и поддерживает указанное направление. Если на выходе первым стоит воркер, при запуске он может проверить значение, заданное в конфигурации. Чтобы применить изменения конфигурации воркера, перезапустите Decoy.

Одноразовая команда преобразования должна завершиться за 5 секунд. Преобразование завершится ошибкой, если объём `stdout` превысит 16 МиБ или `stderr` превысит 64 КиБ. На один процесс Decoy приходится не больше восьми таких команд одновременно. Если все восемь уже работают, Decoy не запустит ещё одну и вернёт ошибку преобразования.
