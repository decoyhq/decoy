# Конфигурация

`decoy serve` принимает флаги, файл конфигурации YAML или то и другое. Флаги имеют приоритет над файлом.

Если вы прошли [быстрый старт](../quick-start/index.mdx), сохраните этот файл рядом с `collections.yaml`, чтобы применять те же настройки без повторного ввода флагов:

```yaml title="mocks/decoy.yaml"
routes: routes # directory of Route files, relative to this file
collections: collections.yaml
port: 8080
```

В каталоге проекта выполните:

```sh title="Start Decoy and watch for edits"
decoy serve --config mocks/decoy.yaml --watch
```

Добавьте разовый флаг, например `--port 8081`, чтобы переопределить настройку без редактирования файла.

## Настройки

| Ключ файла           | Флаг                     | По умолчанию                                                      |
| -------------------- | ------------------------ | ----------------------------------------------------------------- |
| `routes`             | `--routes <dir>`         | Обязательный параметр                                             |
| `collections`        | `--collections <file>`   | Обязательный параметр                                             |
| `port`               | `--port <port>`          | `8080`                                                            |
| `host`               | `--host <host>`          | `localhost` (`127.0.0.1` и `::1`)                                 |
| `listeners`          | Нет                      | Нет                                                               |
| `collection`         | `--collection <id>`      | Первая Collection в файле                                         |
| `passthroughBaseUrl` | `--passthrough-base-url` | Нет (см. [Passthrough](../routes/index.md))                       |
| `protos`             | Нет                      | Нет                                                               |
| `tls`                | Нет                      | Нет (обычный HTTP)                                                |
| `maxBodyBytes`       | Нет                      | `33554432` (32 МиБ)                                               |
| `transformers`       | Нет                      | Нет (см. [Настройка Pipeline](../transformer-pipelines/index.md)) |
| `pipelines`          | Нет                      | Нет (см. [Настройка Pipeline](../transformer-pipelines/index.md)) |

`listeners` открывает дополнительные именованные точки прослушивания. У всех те же Routes, Session и Control API, что и у `port`, поэтому клиенты gRPC и HTTP могут использовать разные порты, но одну Session:

```yaml title="decoy.yaml (excerpt)"
port: 8080
listeners: { grpc: 50051 }
```

Имена ключей произвольные; они нужны только для журналов и ошибок. Каждая точка прослушивания обслуживает HTTP и gRPC.

`host` задаёт адрес привязки. Значение `localhost` по умолчанию привязывает и `127.0.0.1`, и `::1`, поэтому клиенты работают с любым адресом, в который у них разрешается `localhost`. IP привязывает только указанный адрес (`0.0.0.0` — все интерфейсы, например внутри Docker); другое имя привязывает все адреса, в которые оно разрешается. У точки прослушивания может быть свой адрес: `{ port: 9000, host: 0.0.0.0 }`. `--host` переопределяет `host` верхнего уровня и адрес основной точки. Порты не должны повторяться независимо от адресов.

`tls` включает HTTPS на всех точках прослушивания с вашим сертификатом и ключом в PEM. ALPN выбирает HTTP/2 или HTTP/1.1 для каждого соединения, поэтому gRPC поверх TLS работает на том же порту. Точка, заданная как `{ port, tls: false }`, остаётся на обычном HTTP, так что можно использовать оба протокола:

```yaml title="decoy.yaml (excerpt)"
tls:
  cert: certs/dev.pem
  key: certs/dev-key.pem

port: 8443 # https
listeners:
  payments: 9443 # https
  legacy-crm: { port: 8080, tls: false } # http
```

`port` поддерживает ту же форму объекта (`{ port, host, tls }`). `--port` меняет только номер порта. Клиенты должны доверять сертификату; для Node.js можно задать `NODE_EXTRA_CA_CERTS=certs/dev.pem`.

С `tls: auto` указывать файлы сертификата не нужно: при каждом запуске Decoy подписывает новый сертификат для localhost сроком на год с помощью локального центра сертификации (CA) в `.decoy/` рядом с конфигурацией (`ca.pem`, `ca-key.pem`). CA создаётся один раз и используется повторно, поэтому достаточно один раз добавить его в доверенные (`NODE_EXTRA_CA_CERTS=mocks/.decoy/ca.pem`, в grpc-js — `credentials.createSsl(ca)`). Если `ca.pem` пропадёт, он будет восстановлен из ключа. Decoy записывает `.gitignore` в `.decoy/`, чтобы ключ CA не попал в Git.

```yaml title="decoy.yaml (excerpt)"
tls: auto
```

`protos` загружает схемы protobuf для gRPC:

```yaml title="decoy.yaml (excerpt)"
protos:
  roots: [../proto] # import paths; every .proto under them is compiled at startup
  descriptorSets: [build/api.binpb] # optional precompiled FileDescriptorSets
```

С `files` компилируются только подходящие входные файлы, а не все `.proto` в корневых каталогах. Их импорты по-прежнему разрешаются через `roots`. Каждый шаблон должен найти хотя бы один `.proto` в корневых каталогах:

```yaml title="decoy.yaml (excerpt)"
protos:
  roots: [../proto]
  files: [../proto/services/catalog/**/*.proto]
```

`roots` работает как флаги `-I` в protoc: по этим каталогам разрешаются импорты. Если импорты заданы от верхнего каталога (`import "v1/keyboards/keyboards.proto";`), укажите только его. Если каждый каталог импортирует соседние файлы по имени (`import "keyboards.proto";`), перечислите все такие каталоги:

```yaml title="decoy.yaml (excerpt)"
protos:
  roots: [../proto, ../proto/v1/keyboards, ../proto/v2/my-entity]
```

## Transformers и Pipelines

Ключи верхнего уровня `transformers` и `pipelines` задают переиспользуемые шаги и именованные списки входных и выходных шагов. Именованный Pipeline можно выбрать в Routes HTTP, gRPC и WebSocket. Инструкции и ссылки по транспортам см. в разделе [Настройка Pipeline преобразований](../transformer-pipelines/index.md).

## Проверка при запуске

Пути в файле разрешаются относительно самого файла, а пути во флагах — относительно рабочего каталога. Запуск прерывается с диагностикой в следующих случаях: неизвестные ключи в конфигурации, Routes или Collections; нечитаемые файлы; некорректные Routes или Collection; повторяющиеся ID Routes или Collections; порт указан дважды или уже занят; отсутствуют корневые каталоги proto; шаблон `files` не нашёл ни одного файла; proto-файлы не компилируются; сертификат или ключ TLS не читаются либо не соответствуют друг другу; не читается CA в `.decoy/`; неизвестна стартовая Collection; воркер не запускается; указан неизвестный Transformer или неподдерживаемое направление Pipeline; проверка `check` воркера отклонила выходной литерал.

## Перечитывание конфигурации {#reloading}

`--watch` (для `decoy serve` и `decoy` без подкоманды) перечитывает конфигурацию при изменении файла конфигурации, Collections, Route, `.proto` в корневом каталоге (с `files` — выбранного файла, его импорта или нового файла, подходящего под шаблон) либо набора дескрипторов. В терминальном интерфейсе, который открывает `decoy` без подкоманды, `/reload` делает то же по запросу.

```sh title="Start Decoy and watch for edits"
decoy serve --config mocks/decoy.yaml --watch
```

Decoy перечитывает и заменяет все настройки, не останавливая сервер. Открытые соединения остаются открытыми, а уже выполняющиеся запросы завершаются на старой конфигурации. Selection сохраняется: если нужного Behavior больше нет, переопределение удаляется с предупреждением; если исчезла выбранная Collection Session, Session возвращается к `collection` по умолчанию; Sessions, которые не выбирали Collection, переходят на новое значение по умолчанию. Если файл не разбирается или не проходит проверку, остаётся старая конфигурация, а ошибка выводится один раз за сохранение. Изменения `port`, `host`, `listeners` и `tls` требуют перезапуска и выводят `listener changes need restart`. Изменения определений Transformer workers тоже требуют перезапуска и выводят `Transformer worker changes need restart`. Если `routes`, `collections` или `protos` теперь указывают в другое место, наблюдение переключается на новые пути.

Изменения обнаруживаются примерно через секунду после последней записи. На сетевых файловых системах и на дисках Windows из WSL2 (`/mnt/c/...`) события файлов не приходят, поэтому Decoy опрашивает файлы. `--watch-poll` включает опрос в любом месте и подразумевает `--watch`.

## Ограничения и остановка

- Тела запросов больше `maxBodyBytes` (по умолчанию `33554432`, 32 МиБ) не буферизуются: клиент получает `413`, а в gRPC — `RESOURCE_EXHAUSTED`. Для больших загрузок поднимите лимит, например `maxBodyBytes: 104857600`.
- Ctrl+C или SIGTERM останавливает `decoy serve`: сервер прекращает принимать запросы, даёт текущим запросам 5 секунд на завершение (длинный `delay` или медленная Passthrough не продлят ожидание), затем выходит с кодом 0.
