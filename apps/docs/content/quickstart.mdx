---
title: Serve your first mock
description: Return a user, then change the same request to a 404 while Decoy is running.
---

Make `GET /users/123` return Ada. Once you see the response, add a second outcome and switch to it while the server is running.

## Install the CLI

For a project install, run the command in the directory containing your package manifest. In an empty directory, run `npm init -y` first. You will also need a POSIX shell and curl.

```sh
npm i -D @decoyhq/cli
```

[Install a standalone binary](guide/install.md).

## Define the user response

Create a folder for your mock files.

```sh
mkdir -p mocks/routes
```

Save the following [Route](terms.md#route) as `mocks/routes/users.yaml`. It handles `GET /users/{id}`. The `user-123` [Case](terms.md#case) picks requests for ID `123`, and its `success` [Behavior](terms.md#behavior) returns Ada.

```yaml title="mocks/routes/users.yaml"
id: users-by-id
transport: http
match: { method: GET, path: '/users/{id}' }
cases:
  user-123:
    match: { pathParams: { id: '123' } }
    behaviors:
      success:
        status: 200
        body: { id: '123', name: Ada }
```

Create a [Collection](terms.md#collection) named `happy-path` so Decoy starts with the `success` response.

```yaml title="mocks/collections.yaml"
- id: happy-path
  routes: [users-by-id:user-123:success]
```

## Request the user

Run the server from the directory containing `mocks/`. Leave this terminal open. The `--watch` flag lets you edit the files in the next step.

```sh
npm exec --package=@decoyhq/cli -- decoy serve --routes mocks/routes --collections mocks/collections.yaml --port 8080 --watch
```

In a second terminal, request the user.

```sh
curl -i http://localhost:8080/users/123
```

Look for **200 OK** and this response body:

```json
{ "id": "123", "name": "Ada" }
```

## Switch to a 404

Replace the Route file with this version. It adds a second Behavior named `missing` beside `success`.

```yaml title="mocks/routes/users.yaml"
id: users-by-id
transport: http
match: { method: GET, path: '/users/{id}' }
cases:
  user-123:
    match: { pathParams: { id: '123' } }
    behaviors:
      success:
        status: 200
        body: { id: '123', name: Ada }
      missing:
        status: 404
        body: not found
```

Append a second Collection to `mocks/collections.yaml`. Its [Behavior address](terms.md#behavior-address) ends in `missing`, so the same request now has a different response available.

```yaml
- id: user-missing
  routes: [users-by-id:user-123:missing]
```

After Decoy reloads the files, switch Collections from the second terminal.

```sh
curl -X POST http://localhost:8080/__decoy__/control/useCollection \
  -H 'content-type: application/json' \
  -d '{"collection":"user-missing"}'
```

Repeat the original request. This time you'll see **404 Not Found** and the body `not found`.

```sh
curl -i http://localhost:8080/users/123
```

Stop Decoy with Ctrl-C in the server terminal.

To match another user, add a [Case](guide/routes.md#case-match). To switch this response from a browser test, follow the [Playwright](guide/playwright.md) or [Testplane](guide/testplane.md) setup.
